What this is

    
hookrelay is the family's only front door for alerts, and its only way out — the pipe.
    It adapts every monitoring dialect into one normalized event, routes it to the processing
    systems (the judge, the investigator), then dresses whatever comes back into each channel's
    card format and delivers it. It is deliberately content-blind: judgement belongs to the
    brains, and the pipe answers for the mechanics — every message accounted for, every delivery
    with an outcome.


    
One alert's journey

    
upstream POST /hook/{source}
  -> extract (templates + level_map) -> gates (dedup / silence / storm fuse)
  -> routes (accumulate by priority, stop truncates) -> channels (render per type)
  -> delivery (retry with backoff, dead letters visible + self-alarm)
  -> ledger (decision chain + the bytes of both directions)


    
Reading this board

    

      
AreaHow to read it

      
The now tabOne card per operation — an alert and everything that quoted it — newest first, each drawn as the same seven stages: received · judged · notified · investigated · a person · condition · fix. A filled dot is a stage that happened, the wait between two stages sits on the line, and the colour is earned: amber is a card that asked somebody something and got no press, green is a condition that ended or a fix that held, red is a fix that did not hold or a dead letter. The pill and the line under the dots say what the alert needs now. Open a card for the whole story

      
The four numberswaiting on you counts cards with a button nobody pressed; in flight counts alerts handed to a node with nothing back yet; dead letters deserve a human (with HOOKRELAY_ALARM_URL set they alarm on their own); ended well is the last day's conditions that ended or fixes that held

      
The journey tabThe same seven stages for one alert, from any handle it left behind — its id, the hr- correlation a brain quoted, a session key, a work id, or the platform id of a card — with everything each stage said. Resolved from this ledger alone; a hop a node owns links to that node's console (HOOKRELAY_UI_LINKS)

      
The ledger tabEvery event as the pipe recorded it: the decision chain gate by gate, where it was delivered, and on opening a row the round trip — the payload as received, the exact body sent per channel, what each brain sent back. The forensic view; the now tab is the reading view

      
The refresh controlThis page keeps no clock. It holds one streaming connection to /live and refetches what you are currently looking at when the service says something changed — so an alert storm is one refetch, not a tick per event. ↻ refetches on demand, the badge beside it reads live or offline (a dropped stream reconnects on its own, backing off), and the stamp top-right says when the data is from

      
The config tabAn editor for config.yaml (the file is the source of truth): it only writes when validation passes, and applies hot — no restart. Needs the admin token

    


    
API quick reference

    
Addresses depend on where you are: inside the family's docker network use http://hookrelay:8100; from the host, the loopback mapping http://127.0.0.1:8100. Read endpoints take X-Read-Token, admin endpoints X-Admin-Token — remember either one on the page and you never type it again.

    

      
EndpointPurpose

      
POST /hook/{source}The front door. Each source is declared in config.yaml with its signature, templates and level map

      
GET /status · GET /timelineWhat the ledger and now tabs read: recent events with their decisions and deliveries; the same events gathered into chains

      
GET /trace/{id} · GET /audit/{id}One alert's whole journey, bytes included — {id} is an event id, hr-…, a session key, a work id or a card's platform id; and the same operation as an accountability record with digests instead of bytes

      
POST /explain/{source}Dry run: what this payload WOULD do — nothing recorded, nothing delivered, no brain called (admin)

      
GET/PUT /config · POST /config/reloadRead, replace and hot-reload the config (admin)

      
POST /silences · DELETE /silences/{id}The silence valve (admin)

      
POST /deliveries/{id}/retryA dead letter's second chance (admin)

      
GET /unseen · GET /metricsCards nobody has opened, asked of the bridge on demand; Prometheus text: events, deliveries, outbox depth, fuse state (read token)

    


    
The config that matters (config.yaml)

    

      
ConceptIn one line

      
sourcesPer door: the signing secret, extraction templates (placeholders pull title/body/level) and level_map to normalize each vendor's wording. A ${NAME} in the config expands from .env — adding one needs no compose edit

      
routesOrder is meaning: matches accumulate from highest priority down, and stop: true truncates. The return routes (judge-notify / probe-notify) sit highest and stop, so a result is never processed a second time

      
channelspayload: normalized sends the standard event (for a brain); processed renders a brain's result as a Feishu/DingTalk card; raw passes the original payload through

      
Noise controlFingerprint dedup (fingerprint_fields + window), silences, and the storm fuse (volume, not content)

      
RetentionHOOKRELAY_RETENTION_DAYS (14 by default) prunes the ledger with everything else

    


    
Its place in the family

    
The escalation routes copy every front-door event to the investigator
    (${HOOKPROBE_EVENT_URL}). The judge and the investigator both return through their
    own doors speaking the same brain-result dialect, and the pipe dresses both for the channels.
    And when the pipe itself is what broke, the dead-letter self-alarm posts straight to
    HOOKRELAY_ALARM_URL, around the stack that just failed.

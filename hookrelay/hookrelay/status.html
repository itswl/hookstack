这是什么

    
hookrelay 是家族唯一的告警前门，也是唯一的出口 — 管道。它把各家监控的方言适配成
    统一事件，按路由送去处理系统（判官/调查员），再把回来的结果打扮成各渠道的卡片投递出去。
    它刻意不理解内容：判断是大脑们的事，管道只负责「每条消息有交代，每次投递有结局」。


    
一条告警的旅程

    
上游 POST /hook/{source}
  → 提取(模板+level_map) → 门(去重/静音/风暴熔断)
  → 路由(按优先级累积，stop 截断) → 渠道(按类型渲染)
  → 投递(重试退避，死信可见+自告警) → 账本(决策链+收发双向原文)


    
读这块板子

    

      
区域怎么读

      
三张卡排队=在等投递；死信>0 应当有人看（配了 HOOKRELAY_ALARM_URL 会自动报警）

      
事件行点开=完整决策链：哪些路由被考虑、为何命中/跳过、投递到哪。「对比」按钮拉 /trace 往返视图：原始载荷、每渠道发出的 body、各大脑的回件

      
配置 tabconfig.yaml 的编辑器（文件才是真源）：校验通过才落盘，热加载不重启。需要 admin token

    


    
API 速查

    
地址按部署形态：家族容器网络内用 http://hookrelay:8100，宿主机用回环映射 http://127.0.0.1:8100。读接口带 X-Read-Token，管理接口带 X-Admin-Token（都在页面里记住过就不用手填）。

    

      
端点用途

      
POST /hook/{source}前门。source 在 config.yaml 里声明（含签名/模板/级别映射）

      
GET /status · GET /trace/{id}板子的数据源 / 一条告警的完整往返（含双向原文取证）

      
POST /explain/{source}干跑：这个载荷「会」发生什么 — 不记账不投递（admin）

      
GET/PUT /config · POST /config/reload配置读改与热加载（admin）

      
POST /silences · DELETE /silences/{id}静音阀（admin）

      
POST /deliveries/{id}/retry死信的第二次机会（admin）

      
GET /metricsPrometheus 文本：事件/投递/积压/熔断（read token）

    


    
配置要点（config.yaml）

    

      
概念一句话

      
sources每个门的签名密钥、提取模板（占位符抽标题/正文/级别）、level_map 统一各家用词。配置里的 ${NAME} 从 .env 展开 — 加变量不用改 compose

      
routes顺序即语义：按优先级从高到低累积匹配，stop: true 截断。回传路由（judge-notify/probe-notify）优先级最高并 stop，防止结果被再次加工

      
channelspayload: normalized 发标准事件（给大脑）；processed 把大脑结果渲染成飞书/钉钉卡片；raw 透传原始载荷

      
防噪三件套指纹去重（fingerprint_fields + 窗口）、静音、风暴熔断（按量不按内容）

      
保留HOOKRELAY_RETENTION_DAYS（默认 14）连账本一起清

    


    
在家族里的位置

    
升级路由把每个前门事件复制给调查员（${HOOKPROBE_EVENT_URL}）；判官与调查员的
    结果走各自回传门回来，说同一种「大脑结果方言」，管道统一穿衣送渠道。管道自己坏了怎么办 —
    死信自告警直发 HOOKRELAY_ALARM_URL，绕开刚坏掉的那套栈。

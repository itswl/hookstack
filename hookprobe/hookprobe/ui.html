这是什么

hookprobe 是一个只读的告警调查员：拿到一条值得深挖的告警，它会跑一次会用工具的智能体调查（日志、指标、它自己的案卷，必要时开浏览器），写出结论先行的简短报告。它通常待在 hookstack 家族里：管道（hookrelay）把重要告警抄送过来，写完的报告再经管道回到和判定相同的渠道；任何说 OpenClaw 方言的调用方也可以直接驱动它。

三步开始

1. 在右上角的设置里填好访问口令（只存在这个浏览器里，每个浏览器填一次）。
2. 在「会话」里点新会话，用一句话描述要调查什么，比如「对这个容器做一次只读的健康巡检，结论先行」。
3. 运行时实时看它的处理过程，随时可以停止；跑完之后，底部的输入框就是追问：同一个引擎会话会接着第一轮的全部证据继续。

接口速查（给 AI 或脚本用）

每个请求都带 Authorization: Bearer <口令>。轮询约定：运行中 /final 回 202；一旦回 200，isFinal 一定是 true，第一次确认的读取就可以相信。下面的例子用 docker 网络里的地址 http://hookprobe:8088；在本机用 http://127.0.0.1:8088。

# 开始一次调查（兼容 OpenClaw 的约定）
curl -X POST http://hookprobe:8088/hooks/agent -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"message":"要调查什么…","sessionKey":"my:task:1","timeoutSeconds":900}'

# 取结果（202 = 还在跑；200 => {"isFinal":true,"text":"完整报告"}）
curl http://hookprobe:8088/sessions/my:task:1/final -H "Authorization: Bearer $TOKEN"

# 在同一个会话里追问 / 停止正在跑的一轮
curl -X POST http://hookprobe:8088/sessions/my:task:1/continue -H ... -d '{"message":"追问"}'
curl -X POST http://hookprobe:8088/sessions/my:task:1/stop -H ...

安全模型（为什么可以无人值守）

只读分三层：只读凭证（真正的边界，只挂载查询级别的身份）→ bash 守卫（拒绝 kubectl、systemctl、terraform 等的变更动作，子智能体里也一样）→ 一次性容器（非 root）。在此之上还有：预算熔断（窗口内花费到了上限，事件入口就拒绝新调查，并在卡片上说明）、幂等（一场告警风暴只资助一次调查，不是 N 次），以及失败也会闭环（超时、崩溃、重启或被拒，都会回一份报告）。

报告卡片上的按钮按下后落在 POST /hooks/action，和事件入口一样由管道签名。按钮只代替控制台对处置建议的那一次点击，不能做别的：白名单是运维在主机上编辑的文件，任何按钮都碰不到它。每次按键先按 (correlation_id, kind, at) 认领再执行，所以聊天平台没收到回应时的重投递，买不到第二轮，也批准不了两次。

循环卫生（运行的上下文和账单）

重复提醒第 HOOKPROBE_REPEAT_REMINDER_AT 次（默认第 3 次，之后每个倍数）完全相同的调用，工具结果里会带一句提醒：换个办法，或者记下还不知道的然后继续。预算熔断是事后止损，这是花钱之前的提醒
命令时限HOOKPROBE_BASH_TIMEOUT_MS / HOOKPROBE_BASH_MAX_TIMEOUT_MS 限制单条命令，不让一个连不上的 curl 占着名额直到整次运行超时
花了多少每一轮都有自己的账单行：模型、输入输出词元、缓存读写、美元、秒数。会话的累计在标题下面，右上角的标签是整个窗口的花费（设置了 HOOKPROBE_BUDGET_USD 时旁边是上限）
值不值花费柱状图下面那一行：N 次调查、花了多少、裁定的里面几次找到了原因。它来自报告卡片上的「找到原因 / 没找到」按钮；没人裁定的调查算作未评价，从不算作失败
上下文复用率提示词的全部组成（新输入、从缓存读回的、写进缓存的）里，读回的比例。写入按付费算，因为它确实更贵。一次调查在提到告警之前就带着约 29k 词元的框架开销，所以复用是唯一剩下的杠杆：在这里追问大约比新开一次调查便宜十倍
输入记录每一轮都记下它得到了什么：模型、技能层和名字、角色、MCP 服务，以及环境记忆和调查方法的摘要。在任何一轮上打开「输入 · 模型拿到了什么」就能看到，文件后来改过也会标出来

小技巧

  • 装一个市场上的技能：解压到 /data/.claude/skills/<名字>/（去掉 __MACOSX），下一次运行就会加载。先读一遍：技能是在指挥一个拿着你凭证的智能体
  • 加一个角色：在「角色」里打开任意内置角色，复制、改名、保存；或者直接放一个 .md 文件
  • 接一个 MCP 服务：编辑 /data/mcp.json（市场的 config.json 格式可用，enabled:false 会跳过），在「系统」里确认，下一次运行就用上
  • 控制一个会话能看到哪些技能：用 HOOKPROBE_SKILLS 白名单；各层用 HOOKPROBE_SETTING_SOURCES 切换
  • 问「它到底做了什么」：看「审计」，按会话筛选；单次运行的过程在会话里的「处理过程」下面
  • 刷新：页面不设时钟，它和 /v1/live 保持一条流式连接，服务说有变化时才重新读取你正在看的内容。刷新按钮随时手动刷新，旁边的标记显示连接状态。正在看的运行有自己的推送流，跑完就停
  • 定时巡检：主机上一条 crontab，向管道的前门 POST 一个「巡检到期」事件就够了，报告会走平常的渠道

更完整的设计和部署说明在 hookprobe/README.md 和仓库根目录的 OVERVIEW.md。

What this is

hookprobe is a read-only alert investigator: given an alert worth digging into, it runs one tool-using agent investigation (logs, metrics, its own case files, a browser when needed) and produces a short report with the conclusion first. It normally sits inside the hookstack family — the pipe (hookrelay) copies important alerts over, and the finished report travels back through the pipe to the same channels as the verdict — but any OpenClaw-dialect caller can drive it directly.

Three steps to start

1. Put your bearer token in Settings, top right (kept in this browser only, once per browser).
2. In Sessions, press New session and describe the investigation in a sentence (e.g. "run a read-only health patrol of this container, conclusion first").
3. Watch the live process feed while it runs and Stop it any time; when it finishes, the box at the bottom is a follow-up — the same engine session resumes with all of the first round's evidence intact.

API quick reference (for an AI or a script)

Every request carries Authorization: Bearer <token>. Polling contract: /final answers 202 while running; on a 200 isFinal is always true — trust the first confirming read. The examples use the docker-network address http://hookprobe:8088; from the host, http://127.0.0.1:8088.

# start an investigation (OpenClaw-compatible contract)
curl -X POST http://hookprobe:8088/hooks/agent -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"message":"what to investigate…","sessionKey":"my:task:1","timeoutSeconds":900}'

# poll for the result (202 = running; 200 => {"isFinal":true,"text":"the full report"})
curl http://hookprobe:8088/sessions/my:task:1/final -H "Authorization: Bearer $TOKEN"

# follow up in the same session / stop the turn in flight
curl -X POST http://hookprobe:8088/sessions/my:task:1/continue -H ... -d '{"message":"a follow-up question"}'
curl -X POST http://hookprobe:8088/sessions/my:task:1/stop -H ...

Safety model (why it can run unattended)

Read-only in three layers: read-only credentials (the real boundary — only query-grade identities are mounted) → the bash guard (denies mutating verbs of kubectl/systemctl/terraform and friends, inside subagents too) → a disposable container (non-root). On top of that: the budget breaker (once the window's spend hits the ceiling the event door refuses new investigations — and says so on a card), idempotency (an alert storm funds one investigation, not N), and failure completes the loop (timeout, crash, restart or refusal all return a report).

A report's card carries buttons, and POST /hooks/action is where a press lands — signed by the pipe exactly like the event door. A press stands in for the console click on a remediation proposal and for nothing else: the allowlist is a file an operator edits on the host, and no button can reach it. Each press is claimed by (correlation_id, kind, at) before anything runs, so the redelivery an IM platform sends when it does not hear an answer cannot buy a second turn or approve twice.

Loop hygiene (the run's context and bill)

repeat reminderOn the HOOKPROBE_REPEAT_REMINDER_AT-th identical call (3rd by default, and every multiple after) the tool result carries a note: change approach, or record what stays unknown and move on. The budget breaker stops spending after the fact; this is the nudge before it costs
command deadlinesHOOKPROBE_BASH_TIMEOUT_MS / HOOKPROBE_BASH_MAX_TIMEOUT_MS cap a single command, so a curl at an unreachable host cannot hold a slot until the whole run times out
what it costEach turn carries its own line — model, tokens in/out, cache reads and writes, dollars, seconds. The session's running total sits under its title, and the chip top-right is the whole window's spend (with the ceiling next to it when HOOKPROBE_BUDGET_USD is set)
was it worth itThe line under the spend bars — N investigations, $X, M of the ruled ones found the cause. The rulings come from the Found the cause / Missed it buttons on the delivered card; an investigation nobody ruled on is unrated, never counted as a miss
context reuse %Of everything the prompts were made of — fresh input, tokens read back from the cache, tokens written to it — the share that was read back. Writes count as paid, because they are. An investigation carries about 29k tokens before its alert is even mentioned, so reuse is the only lever left: a follow-up here is roughly ten times cheaper than opening a new investigation
inputs recordEvery turn records what it was given — model, skill layers and names, roles, MCP servers, and digests of the environment memory and appended methodology. Open inputs · what the model was given on any turn; a file edited since is marked

Recipes

  • Install a marketplace skill: unzip it into /data/.claude/skills/<name>/ (drop __MACOSX); the next run loads it — read it first, a skill instructs an agent holding your credentials
  • Add a role: open any seeded role in Agents → copy, rename, save; or drop a .md file in place
  • Wire an MCP server: edit /data/mcp.json (the marketplace config.json dialect works, enabled:false is skipped), confirm in System, the next run picks it up
  • Control which skills a session sees: the HOOKPROBE_SKILLS allowlist; layers are switched with HOOKPROBE_SETTING_SOURCES
  • Ask "what did it actually do": Audit, filtered by session; a single run's feed is under its process steps in Sessions
  • The refresh: this page keeps no clock. It holds one streaming connection to /v1/live and refetches what you are looking at when the service says something changed. The refresh button refetches on demand and the badge beside it says whether the connection is up. A run you are watching has its own pushed stream, which stops when it settles
  • Scheduled patrols: a host crontab that POSTs a "patrol due" event to the pipe's front door is enough — the report travels the usual channels

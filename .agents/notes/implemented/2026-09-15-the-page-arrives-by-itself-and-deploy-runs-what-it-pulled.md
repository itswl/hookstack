## Decision

Two small mechanisms, both about a fact that existed and was not read.

`scripts/weekly_page.sh` runs `cost_report.py` from inside the compose
network on a timer, writes the page to a dated file under `WEEKLY_PAGE_DIR`,
and posts its headline lines (measured, priced, golden gate, kept from a
person, loudest condition, declined at the door, budget) through the pipe's
watch door at level `low`, origin `weekly-page`, kind `report`. The host
crontab fires it Monday 01:05 UTC. Tokens are read from the running
containers' environment; only the door secret is copied into a file the
container can read (the deployment `.env` is mode 600 and holds every other
secret this stack has — the first run mounted it whole and the container could
not read it, which was the right failure).

`scripts/deploy.sh` re-executes itself after its own `git pull`, with the pull
skipped, so the deploy runs the script it just fetched.

## Why

The page had no timer. It was generated by hand — in practice by an agent
mid-session — and every host-side run printed the pipe section as unread,
because the pipe publishes no host port and the address people reached for on
the host belongs to another service. A governance page nobody receives on a
Monday is a grep, not a page. The watch door already exists for signals that
need the operator and already reaches the chat where the cards land; `low` is
the level the investigator declines by itself, so a report never funds a run.

bash reads a script file incrementally. `deploy.sh` pulls at its top and runs
the judge's golden gate forty lines later; on 2026-09-14 the deploy that shipped
`--record /data/eval-gate.json` ran the gate from the new checkout with the OLD
command line, wrote no record, and reported success. The fix is the classic
one: after the pull, `exec` the fresh copy with `DEPLOY_NO_PULL=1`. The deploy
that ships this change is the last one to run stale.

## Consequences

- One card a week, Monday morning, with the numbers the digest decision and
  the labelling decisions are waiting on. The dated page stays on the host for
  anyone who wants the whole thing.
- `reports/` is gitignored; pages carry rule names and never enter the repo.
- A `deploy.sh` edit lands the same deploy from here on; the memory note that
  said otherwise is corrected.
